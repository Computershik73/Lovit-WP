# Ловит для Windows Phone 8.1

Неофициальный клиент мессенджера MAX для Windows Phone 8.1 — порт
[Ловита для iOS](https://github.com/Computershik73/Lovit-iOS). Написан на C#
и XAML под WinRT, собирается Visual Studio 2015. Тот же код собирается и
приложением для Windows 10/11 — [Lovit.Desktop](Lovit.Desktop/README.md).

Приложение не связано с разработчиками мессенджера. Как собрать — в
[SETUP.md](SETUP.md).

## Вдохновлено Komet

Ловит вдохновлён **[Komet](https://github.com/KometTeam/Komet)** — открытым
клиентом MAX на Flutter — и без него не появился бы. Komet служил образцом
во всём, что касается протокола: опкоды, вход и пароль второго фактора,
разбор сообщений и разметки, заливка вложений, голосовые и кружки, стикеры,
пуши. Многое здесь — перенос его решений на C# и Windows Phone 8.1; в коде
у таких мест стоит ссылка на исходный файл Komet.

Спасибо команде Komet.

## Что уже работает

**Вход.** Номер, код из SMS, повторная отправка кода, пароль второго фактора,
создание профиля новым номером. Пароль для входа ставится, меняется и
снимается прямо в настройках — без него MAX не пускает на второе устройство.

**Чаты.** Вкладки «все», «новые» и папки аккаунта — папка это правило отбора
(непрочитанные, каналы, группы, контакты, боты плюс поимённый список), и
состав считается на месте. Счётчик непрочитанного, имя отправителя в группах,
приглушённые названия у чатов с выключенными уведомлениями. Долгое нажатие —
тишина, очистка истории, выход.

**Переписка.** Открывается там, где чтение прервалось: первое непрочитанное
сообщение под самой шапкой. Если непрочитанных мало и они не заполняют
экран, прокрутка упирается в конец раньше — первое из них видно целиком, а
пустоты под последним сообщением не остаётся. Прочитано всё — открывается
в самом низу. Оба случая делает одно действие: прокрутка не уходит дальше
конца списка.

История с догрузкой при прокрутке вверх, разделители дней,
ответы и пересылки с переходом к источнику, реакции строкой, отметка «изм.»,
закреплённое сообщение полоской в шапке, «печатает…», отправка с ответом,
удаление у всех, закрепление. Удалённое собеседником пропадает сразу, не
дожидаясь перезахода. Открытие на найденном сообщении грузит историю с
обеих сторон от него.

**Вложения.** Фотография или файл со скрепки в строке ввода; набранное к
этому времени уходит подписью того же сообщения, а не отдельным. Заливка
в два шага, как в оригинале: протоколом берётся адрес на CDN, тело уезжает
обычным POST — фотография формой, файл сырым телом. Перепутать их нельзя,
сервер молча не примет.

Выбрать файл на Windows Phone 8.1 и тут же его получить невозможно: система
показывает свой выбор поверх, приложение при этом уходит с экрана, а
выбранное возвращается новой активацией. Если телефону стало тесно и
приложение успели выгрузить, выбор пропадает — с этим ничего не сделать.

**Разметка в тексте.** Ссылки, жирное, наклонное, подчёркнутое, моноширинное,
упоминания. Сервер шлёт её не тегами внутри строки, а отдельным списком
отрезков в `elements`, и отрезки эти накладываются друг на друга — жирное
внутри ссылки обычное дело. Поэтому текст режется по всем их границам, и у
каждого куска выходит свой набор признаков; порт `text_format.dart` из Komet.
Зачёркивание остаётся обычным текстом: среди `Inline` в наборе Windows Phone
8.1 его попросту нет.

Своя разметка накладывается на выделенное в поле ввода — кнопкой «разметка»
внизу: жирным, наклонным, подчёркнутым, моноширинным. Отрезки хранятся
вместе с куском текста, который покрывают, и перед отправкой сверяются с
ним: живого пересчёта границ при каждом нажатии клавиши нет нарочно — это
отдельный редактор, а ошибётся он так, что жирным окажется не то слово.
Уехавший отрезок ищется по своему куску, а не найдя — отбрасывается.

Ссылки в набранном тексте находятся сами: без этого набранная ссылка
уходила бы простым текстом и у собеседника ссылкой не становилась. Komet
их не ищет — там разметку накладывают целиком руками, — но там для этого
есть свой редактор. Ищутся только со схемой или с «www»: «сходи в ок.ру»
ссылкой не является, и принимать за неё любое слово с точкой нельзя.

Присланный файл показывается плашкой со значком, именем и размером, а по
нажатию открывается —
ссылку на скачивание сервер выдаёт отдельным запросом и ненадолго, поэтому
спрашивается она в миг нажатия. Открывает файл система: своего просмотрщика
ни для одного из мыслимых видов здесь нет и быть не может.

**Пересылка.** Долгое нажатие на сообщение, выбор чата с отбором по
названию. Чужие каналы в списке не показываются: писать туда всё равно
нельзя.

**Фотографии.** Нажатие на снимок в пузыре открывает его на весь экран, с
увеличением щипком и двойным нажатием. Сохранения в галерею нет: оно
потребовало бы у приложения права на всю библиотеку снимков, а больше
ничего этого права здесь не просит.

**Каналы.** Число подписчиков и ссылка в шапке, подписка и отписка одной
кнопкой вместо строки ввода, сведения с описанием и составом.

**Сведения о чате.** Уведомления, открепление, очистка истории, выход,
участники постранично.

**Контакты.** Карточка с присутствием («в сети», «был(-а) 5 мин назад»),
переход в переписку даже без начатого диалога, добавление в контакты,
блокировка. Записан ли человек в книжке, видно по записи `CUSTOM` в его
именах — это имя, которое дали ему мы, а не он себе.

**Поиск.** Четыре раздела сразу: контакты и свои чаты — по памяти, мгновенно;
сообщения по всей переписке и чужие каналы с группами — на сервере.

**Настройки.** Режим невидимки, «не отмечать прочитанным», «не показывать
набор текста», выбор устройства для сервера, пароль для входа, о приложении,
выход из аккаунта.

**Картинки.** Аватарки в списках, в шапке переписки и фотографии со стикерами
прямо в пузырях — через свой разбор WebP. Пока картинка едет, на её месте
буквы на цветном квадрате; цвет выведен из номера чата, поэтому не меняется
от обновления к обновлению.

**Служебные сообщения.** «Чат создан», «участник вышел», «сообщение
закреплено», пропущенный звонок — строкой посередине, без пузыря: это не
чья-то реплика. Готовую строку сервер часто присылает сам, с именем и
падежами, — тогда берётся она.

**Голосовые и кружки.** Запись удержанием кнопки: свайп влево — отмена,
вверх — закрепить запись. Кодирование и разбор — свой Opus
(`native\LovitOpus\`). Кружки записываются с предпросмотром и играют прямо в
переписке; ушедший за край экрана кружок доигрывает в углу.

**Стикеры и видео.** Стикеры, в том числе движущиеся — Lottie через rlottie
(`native\LovitLottie\`). Видео открывается на весь экран, с перемоткой.

**Правка и реакции.** Своё сообщение правится в строке ввода, с разметкой.
Реакции ставятся, меняются и снимаются; чужие приезжают сами.

**Новые чаты.** Сообщение от человека, с которым переписки не было, —
приложение запрашивает сведения о чате и кладёт его в список. Чужие каналы
туда не попадают.

**Имена файлов.** Кириллица в именах вложений, испорченная по дороге
(«ÐÐµÐºÑÐ¸Ñ.pptx»), чинится и в переписке, и в списке чатов
(`Models\BrokenNames.cs`). Свои файлы уходят с именем в виде `%XX` — так
сервер их не портит.

**Плитка.** Число непрочитанных чатов на плитке начального экрана; по
желанию его обновляет и фоновый агент (`Lovit.Background`), когда
приложение закрыто.

**Отметки о прочтении.** У своих сообщений — «✓», когда дошло, и «✓✓»,
когда собеседник прочитал; в группе — когда прочитал хоть кто-то. Берутся
из `participants` чата и пуша NOTIF_MARK, как у Komet. В списке чатов — те
же галочки у последнего своего сообщения.

**Уведомления.** Пока приложение открыто — системное уведомление о
сообщении из чата, который не на экране. Пока закрыто — от фонового агента,
раз в полчаса: своих пушей у неофициального клиента нет. Звук и текст
выключаются в настройках; молчат чаты без звука и каналы.

**Голосовые звонки.** Принять входящий и позвонить самому — из переписки,
кнопкой «позвонить». Своё медиаядро на C вместо libwebrtc
(`native\LovitTls\lovit_call.c`, внутри `LovitTls.dll`): ICE со STUN и
TURN, DTLS-SRTP, RTP с Opus. Звук — MediaCapture и MediaStreamSource в
категории «связь», с системным эхоподавлением; громкая связь. Сигнализация
и SDP — `Backend\Calls\`. Видео и групповых звонков (через медиасервер
MAX) нет; звонок живёт, пока приложение открыто.

Нет историй, опросов и создания групп из интерфейса.

## Журнал

В отладочной сборке (`Debug`) пишется всё: половина здешних бед
проявляется как раз без отладчика — соединение рвётся молча, приложение
закрывает система, чат открывается пустым. В отправляемой (`Release`) —
только падения и заголовок запуска: в остальных строках переписка и имена
собеседников, и людям держать это у себя незачем. Отладочную сборку не
раздавайте. Смотреть — в настройках,
кнопкой «журнал»; файл лежит в `LocalFolder\lovit.log` и по достижении
полумегабайта уезжает в `lovit.old.log`.

Строки помечены областью: `app` — запуск и сон, `tls` — соединение и
разбор пакетов, `api` — запросы и ответы по номерам, `push` — то, что
приходит само, `chat` — открытие переписки и загрузка истории, `mem` —
нехватка памяти. Пинг намеренно молчит, пока не сломается: он уходит
каждые десять секунд и за полчаса вытеснил бы всё остальное.

Значения полей прячутся по тому же списку, что в Komet
(`lib/core/utils/log_redact.dart`): токены, пароли, коды, тексты
сообщений и приметы устройства заменяются звёздочками, номер телефона
обрезается до первых трёх знаков. Журнал показывают вместе с бедой чаще,
чем думают, а токен сессии в нём — это чужой аккаунт целиком.

Своей папки «Документы» у приложений Windows Phone 8.1 нет вовсе — в
`KnownFolders` её не существует, и записать файл в общее место приложение
не может. Поэтому в журнале есть «сохранить»: место выбирает система, а с
ней и то хранилище, которое в ней настроено.

Снять файл с телефона можно и средством из набора Windows Phone, не
выкладывая его наружу:

```bash
"C:\Program Files (x86)\Microsoft SDKs\Windows Phone\v8.1\Tools\IsolatedStorageExplorerTool\ISETool.exe" ts de 6e2c4b31-9c1d-4e36-9a2f-0b18d1c6a101 C:\temp
```

`de` — телефон, `xd` — эмулятор; длинное число это `PhoneProductId` из
`Package.appxmanifest`. Журнал окажется в `C:\temp\...\LocalFolder`.

## Версия клиента и устройство

Клиента MAX под Windows Phone нет и не было, поэтому приложение
представляется Android-телефоном. Какие именно приметы уезжают на сервер —
в `Core\Config\`:

* `ClientVersion.cs` — версия сборки MAX (`26.23.2`, номер `6779`).
  **Её приходится поднимать вслед за настоящим клиентом.** Устаревшей сборке
  сервер не отказывает сразу: в ответ на приветствие он присылает урезанную
  настройку с признаком `app-update-type`, а при входе отвечает «приложение
  устарело, пожалуйста, обновитесь». Приложение этот признак замечает и
  пишет о нём в настройках. Числа те же, что в версии для iOS
  (`MAXSpoofingService.m`), — меняются вместе с ней.
* `DevicePresets.cs` — набор Android-устройств: имя, версия системы, экран,
  часовой пояс. Выбранное видно в настройках и в списке устройств аккаунта
  на сервере.

Проверить, что сервер принимает нынешнюю версию, можно не трогая телефон —
скрипт шлёт настоящее приветствие и печатает ответ:

```bash
python3 tools/session-check.py 26.23.2 6779
```

Пустой ответ с `app-update-type` означает «версия устарела»; у принятой
версии сервер отдаёт полную настройку (`callsSeed`, `reg-country-code` и
прочее). Скрипту нужен `roots.pem` — склеенные `native/LovitTls/certs/*.der`.

Язык (`locale` и `deviceLocale`) всегда русский, даже если у выбранного
устройства пояс лондонский: часть строк — названия системных папок,
например, — сервер переводит сам, по языку устройства, и испанский телефон
приносил в русское окно папку «Canales».

Признак устройства (`deviceId`) при смене телефона в настройках не меняется
нарочно: для сервера новый признак — это вход с нового устройства, со всеми
последствиями вплоть до повторного ввода пароля.

## Отпечаток сборки

`Core\Protocol\ChatCacheFingerprint.cs` — девяносто шесть байт, без которых
сервер считает клиента незнакомым. Настоящий Android-клиент считает три
хеша от собственных файлов (подпись пакета, dex-код, нативная библиотека),
подмешивая `callsSeed` из ответа на приветствие и признак устройства; хеши
файлов подставлены готовыми — считать их нам не от чего.

Отпечаток уезжает дважды: в `mode` при запросе кода и в
`chatCacheFingerprint` при входе. **Без него сервер отвечает на запрос кода
удачей, но SMS не отправляет вовсе** — самый обидный отказ из возможных,
потому что выглядит он как успех.

## Картинки: свой WebP

CDN мессенджера отдаёт изображения только в WebP — и аватарки, и фотографии,
и стикеры. Windows Phone 8.1 такого формата не знает вовсе: ни `BitmapImage`,
ни `BitmapDecoder` его не открывают. Поэтому в `native\LovitWebP\` лежит свой
разбор на libwebp (только декодер: `dec`, `utils` и читающая часть `dsp`),
готовая библиотека — в `Lovit\Native\<арх>\LovitWebP.dll`.

```bash
native\build-webp.cmd
native\build-webp.cmd x86
```

Пиксели отдаются в BGRA с домноженной прозрачностью — ровно в том виде, в
каком их ждёт `WriteableBitmap`; иначе полупрозрачные края стикеров светились
бы белым ореолом на тёмной теме.

Качаются картинки тоже своей криптографией (`Core\Media\MediaHttp.cs`): у CDN
свой удостоверяющий центр, и системный `HttpClient` до него не доходит.
Скачанное лежит в `LocalFolder\media` — до сорока мегабайт, дальше уходит
самое давнее; разобранное — в памяти, до двадцати четырёх мегабайт.

Не всё, что приходит с CDN, — WebP: заметная часть аватарок приходит
обычными JPEG и PNG, и разбирает их система. Уменьшать надо и там
(`DecodePixelWidth`), иначе такая картинка разворачивается целиком, мимо
всех наших пределов.

Считать её вес по `PixelWidth` при этом нельзя: у системной картинки он
показывает размер исходника, а не разобранного — мы просили 192 точки, а
она честно отвечает «полторы тысячи». Кэш от этого верил, что забит под
завязку, и без конца выбрасывал то, что весило доли от заявленного; отсюда
была и вечная перезагрузка картинок, и работа процессора впустую.

Разбираются картинки сразу в том размере, в каком их покажут: аватарка —
до 192 точек по стороне, фотография в пузыре — до 800, на весь экран — до
1600. Это не про качество, а про то, что показать больше негде: CDN отдаёт
аватарку в полторы тысячи точек, а плитка в списке занимает семьдесят две.
Разобранная такая аватарка весит восемь мегабайт вместо ста килобайт, и
сорока чатов хватало, чтобы телефон закрыл приложение. Меньше показанного
не берём никогда, поэтому на глаз разницы нет.

Уменьшение идёт прямо из буфера библиотеки, построчно: полной несжатой
картинки в памяти не оказывается вовсе. И разбирается всегда одна за раз —
именно всплеск от десятка разом (список чатов открывается сразу весь) и
убивал приложение.

Предел в памяти считается байтами, а не картинками, и это важнее, чем
кажется. Пока он считался штуками, ста двадцати аватарок хватало на пару
мегабайт, но в тот же кэш ложатся фотографии из переписки, а снимок
1080×1920 после разбора занимает восемь мегабайт: полтора десятка их
съедали всё, что телефон отводит приложению, и оно закрывалось — тем
вернее, чем дольше листали переписку с фотографиями. Сами картинки при
этом хранятся как есть, без ужатия: меняется не качество, а то, сколько
их лежит одновременно. Вытесняется то, к чему дольше не возвращались, а
когда система сообщает о нехватке памяти, половина кэша уходит сразу.

## Своя криптография

Соединение с сервером идёт не через системный TLS, а через OpenSSL —
`native\LovitTls\`, готовая библиотека лежит в `Lovit\Native\arm\`.

Причина та же, что и в версии для iOS 6. Windows Phone 8.1 умеет TLS 1.2,
но разговаривает так, как решили в 2014 году: свой список шифров, свой набор
кривых и хранилище корней, пополнить которое нечем — система снята с
поддержки. Сертификат `api2.oneme.ru` выдан НУЦ Минцифры, и этого корня на
телефоне нет.

Корни (`native\LovitTls\certs`) вшиты в саму библиотеку — файл в пакете можно
подменить, зашитый в код уже нет. Цепочка проверяется целиком, вместе с
именем узла: сертификат, выписанный другим центром или на другой домен, не
проходит.

Обращаться к соединению можно только по одному за раз, и в `NativeTlsStream`
за этим следит очередь. OpenSSL не позволяет трогать одно соединение из двух
потоков сразу, а выходило именно так: чтение почти всё время сидит внутри
своего вызова в рабочем потоке, и каждая отправка приходилась ровно на это
окно. Виду сломанного при этом не подать — сокет цел, отправка проходит, —
но записи TLS перемешиваются, и сервер перестаёт отвечать. Со стороны
приложения это выглядело как чат, открывшийся пустым, и не проходило до
перезапуска. Той же очередью закрыто и закрытие соединения: освобождать его,
пока в нём читают, — обращение к освобождённой памяти.

Собирается отдельно от приложения:

```bash
native\build.cmd
```

Компилятор берётся из **Visual Studio 2013**, а не 2015: Windows Phone 8.1
живёт на среде выполнения Visual C++ 2013 (`msvcr120_app.dll`), она же
приезжает на телефон пакетом `Microsoft.VCLibs 12.0`, на который ссылается
проект. Сама сборка идёт прямыми вызовами `cl.exe` и `link.exe` — типа
проекта «Windows Phone 8.1 (C++)» в нынешней Visual Studio нет, а компилятор
под ARM и заголовки телефонного набора есть.

OpenSSL 1.0.2l для ARM лежит готовым в `vendor\openssl-wp81-arm`. Под x86
(эмулятор) его нет, и там приложение обходится системным TLS — что именно
работает сейчас, видно в настройках, строкой «Соединение».

## Сборка

Нужны Visual Studio 2015 с компонентами Windows Phone 8.1 и сам SDK 8.1.
Открыть `Lovit.sln` и собрать, либо из командной строки:

```bash
"C:\Program Files (x86)\MSBuild\14.0\Bin\MSBuild.exe" Lovit.sln /p:Configuration=Release /p:Platform=ARM
```

Готовый пакет появится в `Lovit\AppPackages\` — уже подписанным, и рядом с
ним `.cer` с сертификатом.

### Установка на телефон

Телефон должен быть разблокирован для разработчика. Ставится пакет
средством развёртывания из набора Windows Phone 8.1 — окном
`AppDeploy.exe` либо из командной строки:

```bash
"C:\Program Files (x86)\Microsoft SDKs\Windows Phone\v8.1\Tools\AppDeploy\AppDeployCmd.exe" /installlaunch Lovit\AppPackages\Lovit_0.1.0.0_ARM_Test\Lovit_0.1.0.0_ARM.appx /targetdevice:de
```

`/targetdevice:de` — телефон по USB, `xd` — эмулятор; список подключённого
покажет `/EnumerateDevices`. `Add-AppDevPackage.ps1` здесь ни при чём: это
способ для настольных приложений магазина, и в папке пакета его нет.

Конфигурация `x86` собирается для эмулятора, `ARM` — для телефона.
В `Release` включён компилятор .NET Native, поэтому такая сборка идёт
заметно дольше отладочной.

### Номер сборки

Телефон не ставит пакет с той же версией, но другим содержимым — отвечает
«increment the version number of the package to be installed». Отдельного
поля вроде `versionCode` у appx нет, зато версия четырёхчастная, а
пользователю показываются только три первых числа (`AboutPage`). Четвёртое
и есть номер сборки, снаружи невидимый.

Поднимается он сам, шагом `BumpPackageRevision` в `Lovit.csproj`: каждая
сборка пакета увеличивает его на единицу прямо в `Package.appxmanifest`.
То есть файл манифеста после сборки оказывается изменённым — так и задумано,
это и есть счётчик.

`AppxAutoIncrementPackageRevision` для этого не годится: его понимает мастер
«создать пакеты» в Visual Studio, а из командной строки он не делает ничего.

### Подпись

Пакет подписывается самоподписанным `Lovit\Lovit_TemporaryKey.pfx`. В
репозитории его нет — это закрытый ключ, — и для своей сборки его надо
сделать самому:

```bash
powershell -Command "$c = New-SelfSignedCertificate -Type Custom -Subject 'CN=Ваше имя' -KeyUsage DigitalSignature -KeyExportPolicy Exportable -CertStoreLocation 'Cert:\CurrentUser\My' -TextExtension @('2.5.29.37={text}1.3.6.1.5.5.7.3.3'); [IO.File]::WriteAllBytes('Lovit\Lovit_TemporaryKey.pfx', $c.Export('Pfx'))"
```

Имя в `Publisher` манифеста (`Lovit\Package.appxmanifest`) должно совпадать
с `Subject` сертификата, иначе пакет не подпишется. Отпечаток нового
сертификата (`$c.Thumbprint`) надо прописать в `PackageCertificateThumbprint`
в `Lovit\Lovit.csproj` (и в `Lovit.Desktop\Lovit.Desktop.csproj`, он
подписывается тем же ключом): без отпечатка подпись молча не делается — ни
ошибки, ни подписи.

Там же рядом выключен `EnableSigningChecks`, и это не небрежность. Своя
проверка Visual Studio отвергает самоподписанный сертификат с APPX0107
«непригоден для подписывания», хотя он вполне исправен: не просрочен, с
закрытым ключом, с назначением «подписывание кода» и с `Subject`,
совпадающим с `Publisher`. Убедиться просто — `signtool` подписывает им
пакет молча и без единой жалобы. Придирается предварительная проверка,
рассчитанная на сертификат для магазина; сама подпись после её отключения
делается тем же `signtool`, и подпись выходит настоящая.

Проверить, что пакет подписан, можно по наличию `AppxSignature.p7x` внутри
`.appx` — это обычный zip. `signtool verify /pa` при этом всё равно скажет,
что корень цепочки не доверенный: так и есть, сертификат самоподписанный, и
на телефоне его сначала ставят из `.cer` рядом с пакетом.

## Плитки

Плитка Windows Phone — это цветной прямоугольник системы, поверх которого
лежит белый значок, а имя приложения система пишет сама. Поэтому в
`Lovit\Assets\` лежат не готовые картинки с фоном, а белая фигура на
прозрачном: цвет даёт `BackgroundColor` из манифеста и тема телефона.

Значки собираются из исходной иконки:

```bash
python3 tools/make-tiles.py
```

Скрипт вынимает из `tools/icon-source.jpg` белую фигуру и раскладывает её по
размерам: 150×150, 71×71, 44×44, широкая 310×150, экран запуска и логотип
для магазина (он единственный цветной — в магазине его показывают на светлом
фоне). Все файлы с суффиксом `.scale-240` — это 240 % от базового размера,
столько берут телефоны с экраном 720p и выше; на остальных система уменьшит
сама.

## Устройство проекта

```
Lovit/                   приложение для телефона
  Core/Media/            WebP, Lottie, Opus, загрузка и кэш картинок,
                         заливка вложений, запись голосовых и кружков,
                         видео потоком
  Core/                  плитка, ссылки, кэш контактов
  Models/                чат, контакт, сообщение, вложение, стикер
  Backend/               сессия, вход, чаты, папки, поиск, сообщения,
                         стикеры, пароль
  Backend/Calls/         звонки: сигнализация, SDP, сеанс, звук, обёртка ядра
  Pages/                 вход, списки, переписка, сведения, контакт, поиск,
                         выбор чата, фотография, звонок, настройки, пароль,
                         журнал, о приложении
  Ui/                    строки списков, разметка, стикеры, выбор файла
  Native/arm/            собранные LovitTls, LovitOpus, LovitWebP, LovitLottie
  Native/x86/            то же для эмулятора (без TLS)
  Native/x86-uwp/        то же для Lovit.Desktop
Lovit.Shared/            общее с фоновым агентом: протокол (MessagePack,
                         LZ4, опкоды, отпечаток), соединение и TLS,
                         настройки, приметы устройства, журнал
Lovit.Background/        фоновый агент: число непрочитанных на плитке
Lovit.Desktop/           то же приложение для Windows 10/11
native/                  исходники своих библиотек и их сборка
vendor/                  OpenSSL 1.0.2l под ARM, libopus, libwebp, rlottie
tools/                   плитки из иконки, проверка версии клиента
```

Протокол тот же, что в версии для iOS: заголовок из десяти байт
(версия, команда, номер запроса, опкод, признак сжатия и длина) и тело в
MessagePack, при большом объёме — сжатое LZ4. Сервер — `api2.oneme.ru:443`,
поверх TLS 1.2: сервер согласовывает `ECDHE-RSA-AES256-GCM-SHA384`, а корень
цепочки — НУЦ Минцифры, которого в хранилище телефона нет.

Приложение представляется серверу Android-клиентом: под Windows Phone
клиента у MAX нет, и честный ответ здесь означал бы отказ в сессии.
