# Ловит для настольной Windows

Тот же клиент, что и для телефона, собранный как приложение Windows 10/11.
Пакет ставится на обычный компьютер.

## Как это устроено

Исходники приложения **не копировались**: они подключены к этому проекту
ссылками из соседних папок `Lovit` и `Lovit.Shared` и остаются нетронутыми —
один и тот же код собирается и для телефона, и для стола.

Своего здесь ровно три файла — то, чего у телефона и стола не может быть
общего:

* `App.xaml` — системные кисти. Оформление держится на телефонных
  `PhoneAccentBrush` и прочих, которых на столе нет вовсе; здесь они заведены
  поверх здешних системных, и приложение так же следует за темой и цветом
  выделения Windows.
* `FilePicking.cs` — выбор файла. На телефоне он уводит из приложения целиком
  и возвращает выбранное отдельной активацией; на столе это обычное окно.
* `Shims\PhoneButtons.cs` — железная кнопка «назад». Подставка, объявляющая
  то же пространство имён `Windows.Phone.UI.Input`: общий код собирается слово
  в слово, а событие ему подаёт стрелка в заголовке окна. Видимостью стрелки
  распоряжается тоже она — зажигает, когда есть куда возвращаться.

Решение своё, `Lovit.Desktop.sln`: телефонное `Lovit.sln` не тронуто.

## Сборка

    "C:\Program Files\Microsoft Visual Studio\2022\Enterprise\MSBuild\Current\Bin\MSBuild.exe" ^
        Lovit.Desktop\Lovit.Desktop.csproj /t:Restore /p:Configuration=Debug /p:Platform=x86

    "C:\Program Files\Microsoft Visual Studio\2022\Enterprise\MSBuild\Current\Bin\MSBuild.exe" ^
        Lovit.Desktop\Lovit.Desktop.csproj /p:Configuration=Debug /p:Platform=x86

Пакет выходит в `Lovit.Desktop\AppPackages\`.

Последнее число версии растёт само на каждой упаковке — как и у телефонной
сборки. Без этого Windows считает пакет с прежним номером тем же самым и
ставить отказывается: пришлось бы каждый раз удалять предыдущий. Вручную
версию в манифесте не трогать.

## Установка

В папке пакета лежит `Install.ps1` — он же ставит и сертификат. Правой
кнопкой по нему → «Выполнить с помощью PowerShell», от имени администратора.
В Windows должен быть включён режим разработчика (Параметры → Система → Для
разработчиков).

## Родные библиотеки

Те же самые, что на телефоне, но пересобранные под настольную Windows —
системной криптографией приложение не пользуется ни там, ни здесь:

* `LovitTls.dll` — своя криптография, OpenSSL 3.6 внутри статически (на
  телефоне 1.0.2, отсюда одна оговорка в исходнике: замки для потоков
  нужны только старой библиотеке, новая бережёт себя сама);
* `LovitWebP.dll` — разбор картинок;
* `LovitOpus.dll` — кодирование и разбор голоса.

Собираются скриптом `native\build-desktop.cmd` (можно по одной:
`build-desktop.cmd tls`). От телефонных скриптов он отличается только
инструментами: Visual Studio 2022 вместо 2013, набор Windows 10 вместо
телефонного, `WINAPI_FAMILY_APP` вместо `WINAPI_FAMILY_PHONE_APP` и одна
`WindowsApp.lib` вместо трёх телефонных.

OpenSSL берётся из vcpkg, набор `x86-uwp-static-md` — статический, чтобы
библиотека была самодостаточной, как на телефоне:

    C:\vcpkg\vcpkg.exe install openssl:x86-uwp-static-md

## Чего пока нет

**Движущихся стикеров.** `LovitLottie.dll` под настольную Windows ещё не
собрана — стикеры показываются неподвижной картинкой. Остальное на месте.
